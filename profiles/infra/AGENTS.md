# OpenCode Developer Workflow Pack

This repository is a reusable OpenCode workflow pack for AI-assisted software development. The pack is organized like a small engineering team inside OpenCode: primary agents do work, subagents review focused areas, commands provide slash-entry points, and skills provide reusable checklists.

## Quick Start — Which Tool to Use

Not sure where to start? Find your situation below.

| Situation | Command / Agent |
| --------- | --------------- |
| Starting a new feature or large change | `/architect` → plan first, then implement |
| Building a backend feature (API, DB, auth) | `/backend` |
| Building a frontend feature (UI, state, forms) | `/frontend` |
| Fixing a bug (backend) | `/backend` — fix + regression test |
| Fixing a bug (frontend) | `/frontend` — fix + regression test |
| Tests are failing and I don't know why | `/test` |
| Ready to commit my changes | `/commit` |
| Reviewing my own code before opening a PR | `/review` |
| Cleaning up messy code without changing behavior | `/refactor` |
| Security concern or audit | `/security` |
| Creating or updating a Linear ticket | `/linear` |
| Writing or updating documentation | `/docs` |
| Dockerfile or container image work | `/docker` |
| Docker Compose services, volumes, networks | `/compose` |
| GitHub Actions CI/CD workflow | `/github-actions` |
| Nginx routing, TLS, or headers | `/nginx` |
| Pre-deploy sanity check | `/deploy-check` |
| Deploying to staging or production | `/deploy` |

### Common Workflows

**New feature (full cycle):**

```text
/architect  →  /backend or /frontend  →  /test  →  /review  →  /commit
```

**Bug fix:**

```text
/backend or /frontend  →  /test  →  /commit
```

**Deploy:**

```text
/deploy-check  →  review output  →  /deploy
```

**Infra change:**

```text
/docker or /compose or /nginx or /github-actions  →  /review  →  /commit
```

## Structure

OpenCode is filename-driven: agent filenames become agent names, command filenames become slash commands, and each skill is a folder with a `SKILL.md` file.

| Path                  | Purpose                                                            |
| --------------------- | ------------------------------------------------------------------ |
| `.opencode/agents/`   | Primary agents and focused read-only subagents                     |
| `.opencode/commands/` | Slash command entrypoints that route work to agents                |
| `.opencode/skills/`   | Reusable checklists and domain knowledge loaded by agents/commands |

## Primary Agents

Primary agents are called directly and can do work:

- `backend` — API, server, database, auth, validation
- `frontend` — UI, state, forms, API integration
- `docker` — Dockerfile, images, container runtime
- `compose` — Compose services, networks, volumes, healthchecks
- `github-actions` — CI/CD workflows and release automation
- `nginx` — routing, reverse proxy, SSL, security headers
- `deployment` — production readiness, rollback, post-deploy checks
- `linear` — Linear ticket creation/update through MCP
- `tester` — test execution and failure analysis
- `security` — security risk scanning and threat review
- `architect` — larger design and planning work
- `docs` — documentation updates and consistency
- `commit` — clean semantic commits after user confirmation
- `review` — structured code review
- `refactor` — focused cleanup and maintainability work

## Subagents

Subagents are focused specialists. They analyze and report; they should not independently own broad implementation work.

- Backend: `backend/api-analyzer`, `backend/auth-checker`, `backend/db-analyzer`, `backend/performance-analyzer`
- Frontend: `frontend/a11y-checker`, `frontend/state-analyzer`, `frontend/ui-analyzer`, `frontend/performance-analyzer`
- Docker/Compose: `infra/docker-build-analyzer`, `infra/compose-service-analyzer`
- CI/CD and routing: `infra/github-actions-workflow-analyzer`, `infra/nginx-routing-analyzer`
- Deployment/security: `infra/deployment-readiness-checker`, `security/risk-scanner`

## Commands

Commands are the user-facing entry points. The intended command set is:

- `/backend`, `/frontend`
- `/docker`, `/compose`, `/github-actions`, `/nginx`
- `/deploy`, `/deploy-check`
- `/linear`
- `/test`, `/security`, `/architect`, `/docs`
- `/commit`, `/review`, `/refactor`

Command files should stay thin: load the relevant skill, select the right agent, pass user arguments, and state safety expectations.

## Skills

Skills are reusable checklists loaded by agents and commands. The pack ships skills for backend, frontend, testing, security, and Linear, plus infrastructure skills for Docker, Compose, GitHub Actions, Nginx, and deployment.

## Tooling and MCP servers

Beyond the built-in tools (read, grep, glob, edit, bash, …), the pack configures MCP servers in `opencode.json`:

- **context7** (enabled) — fetch up-to-date documentation for any library or framework. Use it before writing non-trivial code against an external dependency; do not rely on memory for API details.
- **playwright** (enable for frontend) — drive a real browser to verify UI behavior.
- **github** (needs `GITHUB_TOKEN`) — PRs, issues, and repository operations.
- **postgres** (needs `DATABASE_URL`) — inspect schema and run read-only queries.
- **linear** (OAuth) — backs the `linear` agent for ticket workflows.

`bash` runs under an allow-list defined in `opencode.json`: read-only inspection, version checks, linters, formatters, and test runners execute without a prompt; state-changing git and anything unrecognized prompts for confirmation; destructive commands are denied. Run safe inspection commands freely — reserve confirmation for operations that actually change state.

## Safety Rules

These apply to every agent in this pack:

1. **Never commit without user confirmation.** Stage changes, show a diff summary, and wait.
2. **Never run destructive commands** (`DROP TABLE`, `rm -rf`, `kubectl delete`, `docker system prune`) without explicit confirmation.
3. **Never expose or log secrets.** Refuse tasks that would write credentials to files, stdout, or commit history.
4. **Prefer small, reversible changes.** One logical change per commit. Avoid large rewrites unless explicitly requested.
5. **Summarize before acting.** When about to make changes, briefly state: what files will change, what the risk is, and whether tests cover it.

## Output Convention

When an agent completes a task, it should report:

```
Changed: <list of modified files>
Risk:    <none | low | medium — with reason>
Tests:   <added | existing | none — with reason>
```

If risk is medium or higher, wait for confirmation before proceeding.
